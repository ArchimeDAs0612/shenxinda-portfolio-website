# 自动迭代与人工审核

## 为什么以前不会定时更新

原有 GitHub Pages 工作流只在 main 提交或手动触发时构建部署，没有定时器、资料检索、变化检测或事实审核。网站是静态发布物，不会因为其他聊天出现新内容自行变化。

## 已建立的两层机制

1. GitHub Actions：每日北京时间09:17运行只读健康检查。检查代码规范、类型、图片路径、构建、公网样式与图片、分享元信息，以及桌面/手机尺寸下的导航、项目展开、轮播、复制邮箱和微信二维码。结果与截图保留7天。机器关机也可以运行；不调用模型、不修改代码、不部署新内容。可在GitHub Actions手动运行「Portfolio scheduled health check」。失败通过GitHub本人的通知设置提醒，不额外接入邮箱服务。
2. Codex 本聊天自动复查：已创建「Portfolio 每三天后台复查」，每三天18:00运行，每次最多15分钟，当日累计施工不得超过60分钟。读取可访问资料，比较当前公开内容，产生缺口建议；已确认素材的路径问题、既有响应式/可访问性问题可做小范围修复，测试后才发布。无变化不制造提交，无行动事项不通知。

本聊天自动任务需要 Mac 开机且 Codex 应用运行；无法读取办公电脑原始文件。没有可访问的资料或授权时，只报告缺口，不假装吸收资料。云端健康检查不是模型驱动的职业内容更新。

GitHub schedule 可能延迟，公开仓库60天无活动可能停用；不能当作精确时钟。三天复查不是无限后台施工。

## 安全边界

- 可以自动检查/修复：已确认地址与图片的失效路径、布局溢出、键盘可访问性、构建或资源加载问题；无事实改动、无工程重构。
- 必须人工确认：新履历、公司描述、课程、项目结论、业务结果/指标、Agent ownership、职业定位、联系方式值。沉默不等于批准。
- 禁止公开：内部字段、SQL、代码、用户/交易数据、样本量、策略阈值、敏感业务指标、系统实现与权限。
- 候选文案仅存本地 `work/reviews/`（Git已忽略），不放 public、不提交公开仓库、不进入构建。不能把原始内部Context放进Change Log。
- AI建议本身不是证据。记录来源与待确认项；用户批准具体公开文案后，才更新 `content/career-content.ts`。
- GitHub 健康任务以只读权限提供硬边界；Codex 可写任务依赖任务规范和提交审查，不宣称它构成绝对的安全隔离。

## 方案选择与费用

- GitHub Actions最适合不依赖Mac的构建、资源和交互检查。现有发布工作流仍然负责已批准提交后的部署。
- Codex原生调度最适合当前已有聊天Context的定期审阅；使用账户当前可用额度，可能受限额、客户端状态和权限影响。
- launchd也能调本地脚本，但仍依赖Mac在线，不能解决模型、资料权限或人工审核问题；本轮不修改Mac系统调度。
- 本轮没有加入OpenAI API调用、API Key或API消费。以后若把模型放进GitHub无人值守运行，需要另行选择认证与付费方式；API计费与ChatGPT订阅额度不同，未获同意不得开通。
