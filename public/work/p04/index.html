P04 / FieldOps

字段能用在哪条策略里？

字段名称像，不代表口径相同；两个字段常一起出现，也不代表规则彼此依赖。FieldOps 把字段、规则与历史证据放在一起，让研究者查得到一项判断的依据。

我的职责
负责联合治理子系统的设计、工程推进和离线验收；明确用途边界、对象关系及人工审核条件。后续承担多个 Agent 子模块的编排与集成推进。
交付状态
联合治理系统可在本地运行。按特征与按策略批量生成、导出治理文档已离线验收；跨 Agent 端到端验证仍在推进。

三类输入，各回答一个问题

  • 特征资产：字段描述什么对象、如何统计，有哪些使用条件？
  • 历史快照：在已观察的版本与时段里，质量、关系与历史表现如何？
  • 策略配置：哪项条件实际引用了这个字段，它在什么逻辑组合里起作用？

P03 钱包与外卖字段研究先交付了语义、使用条件和分业务治理方法。本项目的新增工作是把这些方法同策略解析、历史证据和对象级知识交付连成可运行的系统。

三类容易混淆的判断

引用、依赖与共现，如何区分？

配置中出现某字段，是可回查的引用；它与其他条件如何共同决定规则是否满足，要看逻辑结构。共现只说明对象在指定范围一起出现。Lift 描述相对于独立情形的共现强度，不证明因果；不把整个资产库或生产流量上的 Lift 验证写成既成事实。

LLM 在字段语义识别中处在什么位置？

机器可以提出语义候选，但名称相似不能代替字段合同、计算口径与使用时点。即使利用 LLM 辅助解释，没有可追溯依据的结论也应留待人工确认。这里不宣称 LLM 自动完成了字段归类或策略审批。

离线验收具体验了什么？

评分与首页看板已有功能验收；部分配置的条件解析、关系查询和历史评价有本地工程验证记录。对象文档能够分别按特征与策略批量生成并导出。以上不等于所有来源均已接入，或远端 RAG 已经消费这些文档。

研究者可以带走什么

查一个字段，可以带走它的使用条件及被哪些规则引用的依据；查一条策略，可以回看它依赖的条件、涉及的对象和对应证据。这两类文档为后续 Pattern 候选研究提供输入，而不是自动生成已验证的模式。

系统部署在哪里？

已确认的是本地工程实现与离线交付。跨 Agent 集成仍在验证中。没有把远端知识入库、下游检索消费、无人值守运行或完整生产上线列为已完成成果。
